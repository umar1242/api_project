# Локальные туннели Cloudflare (Quick Tunnels)

В данном проекте для получения HTTPS-ссылок на локальные Mini Apps используется скрипт `start_cloudflared_tunnels.sh`. Он запускает 6 одновременных процессов `cloudflared tunnel --url ...` (так называемые Quick Tunnels).

## ⚠️ Ограничения и особенности работы (Важно знать)

1. **Случайные URL при каждом запуске**  
   Каждый раз, когда скрипт запускает туннели, Cloudflare выдает **новые случайные адреса** (вида `https://random-words.trycloudflare.com`). Скрипт автоматически собирает их, обновляет `.env` и пересоздаёт Docker-контейнеры ботов. Это значит, что если скрипт упал или вы его остановили, старые кнопки в Telegram-боте перестанут работать навсегда.

2. **Отсутствие авто-восстановления при обрыве (SLA не гарантируется)**  
   Cloudflare предоставляет Quick Tunnels только для краткосрочной разработки. Соединение может внезапно оборваться без причины (таймаут, сброс со стороны Cloudflare). Поскольку процессы запущены в фоне без супервизора (используется `setsid ... &`), упавший процесс **не перезапустится**.
   
   *Почему мы не используем супервизор (PM2 / systemd)?*  
   Даже если мы настроим авто-перезапуск упавшего процесса `cloudflared`, он при старте получит **совершенно новый URL**. Для того, чтобы бот начал выдавать этот новый URL пользователям, нужно не только получить его, но и снова обновить `.env` и перезапустить Docker-контейнер этого бота. Поэтому авто-рестарт одиночного процесса здесь бессмысленен. В случае обрыва вам придется просто заново запустить весь скрипт `start_cloudflared_tunnels.sh`.

## 🚀 Как получить стабильные, не меняющиеся URL

Если вам надоело постоянно обновлять ссылки при каждом сбое и вы хотите стабильной работы (как для длительного тестирования, так и для Production), вам необходимо перейти на **Именованные туннели (Named Tunnels)**. 

Для этого потребуется:
1. Зарегистрированный домен, подключенный к Cloudflare.
2. Авторизация на сервере: выполните `cloudflared tunnel login` и перейдите по ссылке в браузере.
3. Создание туннеля: `cloudflared tunnel create api-project`
4. Настройка файла `config.yml` со списком маршрутов (Ingress Rules) для всех ваших сервисов:
   ```yaml
   tunnel: <ID-вашего-туннеля>
   credentials-file: /home/user/.cloudflared/<ID>.json

   ingress:
     - hostname: admin.yourdomain.com
       service: http://127.0.0.1:5173
     - hostname: main.yourdomain.com
       service: http://127.0.0.1:5174
     # ...и так далее для всех 6 портов
     - service: http_status:404
   ```
5. Прописывание DNS: `cloudflared tunnel route dns api-project admin.yourdomain.com` (повторить для всех поддоменов).
6. Запуск: `cloudflared tunnel run api-project`.

В таком сценарии ваши URL **никогда не будут меняться**. Вы один раз пропишете их в `.env` (`ADMIN_WEBAPP_URL=https://admin.yourdomain.com` и т.д.) и забудете про скрипт `start_cloudflared_tunnels.sh`. Именованный туннель можно и нужно завернуть в Systemd для автоматического перезапуска при падениях — ссылки при этом останутся прежними!
