# Сетка телеграм-ботов с единой API системой

Документ описывает полную логику инфраструктуры, состоящей из шести ботов, объединённых общей базой данных, общим движком заданий и общим планировщиком задач.

---

## Состав системы

1. Админ бот — управляющее ядро
2. Серт бот — сертификатные тесты и курсы
3. Регистратор бот — регистрация и учётные записи участников
4. Основной бот — личный кабинет ученика, геймификация
5. Домашка бот — назначение и проверка домашних заданий
6. Материал бот — хранение и выдача учебных материалов

---

## 1. Админ бот

Центральное управляющее ядро всей системы. Из него создаются курсы, группы, варианты тестов, расписания, домашние задания, привязка материалов. Остальные боты (Серт, Регистратор, Основной, Домашка, Материал) в основном работают в режиме выдачи информации пользователю и почти не позволяют редактировать что-либо напрямую в обход админ бота.

Внутри админ бота есть отдельные разделы для управления каждым дочерним ботом:
- раздел создания сертификатных вариантов (Серт бот);
- раздел создания курсов и групп (Регистратор бот);
- раздел управления группами: расписание, правила геймификации, домашние задания, материалы (Основной / Домашка / Материал боты).

---

## 2. Серт бот

Мини апп для сертификатных тестов: ввод ответов, рейтинг учеников, таймер, профиль, постоянные сертификатные тесты, сертификатные курсы с дедлайном, вывод ошибок.

### Типы заданий

**Тип 1 — тест с вариантами.**
4 или 6 вариантов ответа (A–D или A–F). Задания с 6 вариантами всегда идут в конце блока заданий этого типа. Для заданий с 6 вариантами можно дополнительно назначить второй мод — прикрепление рукописного решения, как и для заданий типа 2 и 3.

**Тип 2 — ввод конкретного ответа.**
Открывается клавиатура для ввода ответа. Два мода:
- Мод 1 — только ввод ответа с клавиатуры.
- Мод 2 — ввод ответа + прикрепление файла с решением.

**Тип 3 — письменные работы.**
От 2 до 6 (или более) вопросов на одно задание. Два мода:
- Мод 1 — только ввод конкретных ответов.
- Мод 2 — проверка админом: вместе с вводом ответа участник прикрепляет от 1 до 3–4 рисунков решения. Если выбран этот мод, ученик не узнаёт свой балл до тех пор, пока админ не проверит его задание.

### Создание варианта (со стороны админа)

Процесс идёт по шаблону внутри админ бота:

1. Название варианта.
2. Прикрепление файла задания (PDF, несколько картинок или Word) — бот не вмешивается в содержимое файла.
3. Описание варианта (опционально).
4. Дедлайн — календарь с вводом даты/часа начала и завершения.
5. Ввод количества заданий каждого типа (тип 1, тип 2, тип 3) с выбором мода (проверка админом / просто ввод ответа) для каждого типа.
6. Кнопка «Вводить ответы заданий» — открывает окно с нужным количеством вопросов:
   - для типа 1 — выбор правильного варианта A–D или A–F;
   - для типа 2 и 3 — ввод правильного ответа через математическую клавиатуру (интеграция открытого пакета для набора математических/LaTeX выражений, например на основе MathKeyboardEngine).
7. Все введённые значения автоматически сохраняются в черновик, чтобы ничего не потерялось до завершения ввода.
8. Кнопка «Проверить данные» — итоговая проверка введённого.
9. Кнопка «Готово» — создаётся вариант с кнопкой старта и кнопкой «Поделиться» со специальной ссылкой на этот вариант.

## 3. Регистратор бот

Мини апп, полностью управляемый из админ бота. Собирает информацию о пользователях и создаёт учётные записи участников онлайн-курсов.

### Создание курса

1. Админ нажимает «Создать онлайн курс» внутри соответствующего раздела админ бота.
2. Выбор приоритета курса: бесплатный или платный.
3. Если курс бесплатный:
   - админ создаёт приватную телеграм-группу;
   - добавляет бота в группу и назначает его админом (нужно, чтобы бот мог создавать одноразовые ссылки-приглашения);
   - в интерфейсе появляется список групп, ещё не привязанных ни к одному курсу.
4. Короткое текстовое описание курса.
5. План курса (опционально) — текстом или прикреплённым файлом.
6. После создания курса бот генерирует реферальную ссылку этого курса.

### Регистрация участника

1. Пользователь переходит по реферальной ссылке курса X — бот понимает, что это именно курс X, а не другой.
2. Бот присылает приветствие и сообщение о записи на курс X, ниже — ссылка на мини апп с анкетой именно этого курса.
3. Анкета:
   - ФИО (обязательно);
   - рабочий номер телефона (обязательно);
   - номер телефона родителя/близкого — опционально, с указанием, чей это номер;
   - краткая информация о себе (опционально);
   - план курса — если админ его вводил, отображается для ознакомления.
4. Черновик анкеты не сохраняется: если пользователь выходит из мини аппа в процессе заполнения, анкета не записывается.
5. После заполнения — кнопка «Записаться к занятию» или «Удалить анкету».
6. При нажатии «Записаться»:
   - бот отправляет пользователю ссылку на чат/группу;
   - анкета сохраняется в базу данных;
   - бот ждёт присоединения пользователя к группе;
   - после присоединения бот автоматически создаёт личный кабинет пользователя (имя, номер, курс и т.д.).

### Платные курсы

Тот же сценарий, но после отправки ссылки на группу в личном кабинете появляется дедлайн оплаты. Если участник не платит вовремя:
- админ отправляет предупреждение о возможном исключении;
- либо участник сразу исключается из курса, аккаунт блокируется и через определённое время удаляется из базы (без бана — чтобы пользователь мог участвовать в других курсах).

## 4. Основной бот

Мини апп для учеников, у которых уже есть учётная запись, созданная Регистратор ботом. Личный кабинет включает статус ученика, прогресс по курсу и блок геймификации.

### Личный кабинет ученика

- профиль: ФИО, курс, дата начала обучения, статус (активен / приостановлен / завершил);
- прогресс: сколько занятий пройдено из скольки всего, процент посещаемости;
- блок «Моё расписание»: ближайшие занятия конкретной группы ученика (дата, тема, формат — онлайн/запись);
- блок геймификации.

### Управление группой (со стороны админа)

После того как админ создаёт группу через Регистратор бот, для этой группы автоматически открывается отдельная страница в админ боте. Внутри неё админ может:
- ввести текстовое описание расписания, условий и правил курса;
- открыть календарь для настройки конкретных дат занятий.

### Настройка урока в календаре

Для каждой даты админ указывает:
- тему урока;
- формат — онлайн или записанное видео.

**Если урок — записанное видео:**
- к дате прикрепляется видео из чата с ботом (бот не загружает файл на отдельный сервер);
- можно дополнительно прикрепить документ;
- при наступлении времени дедлайна урока бот автоматически отправляет видео (и документ, если есть) в группу участников.

**Если урок — онлайн-занятие:**
- бот отправляет предупреждение в группу за 10 минут до начала;
- вместе с предупреждением бот отправляет прикреплённые файлы занятия (если есть).

### Геймификация — коины

Начисляются за конкретные измеримые действия:
- посещение онлайн-занятия (фиксируется вручную куратором/админом либо кнопкой «Я на занятии», активной ограниченное время в момент начала урока);
- просмотр записанного видео-урока до конца (автоматически, либо кнопкой «Посмотрел» в Материал боте, синхронизированной с Основным ботом через общую базу);
- своевременная сдача домашнего задания (см. Домашка бот);
- хороший результат сертификатного теста в Серт боте — при превышении установленного порога % начисляется бонус коинов;
- дисциплина/стрик — например, серия из 5 занятий подряд без пропуска даёт бонус.

### Геймификация — штрафы

- пропуск занятия без уважительной причины;
- несданное домашнее задание к дедлайну;
- опоздание на онлайн-занятие (если фиксируется — вручную куратором или через интеграцию с видеоплатформой).

Таблица начислений и штрафов настраивается админом индивидуально для каждого курса через вкладку «Правила геймификации» в интерфейсе группы — значения не зашиты жёстко в коде.

### Рейтинг и ранги

- рейтинг учеников по коинам — внутри группы или внутри всего курса, видимый всем участникам; админ может скрыть рейтинг для конкретного курса;
- ранги/уровни (например «новичок», «активный ученик», «отличник») — визуальный статус, меняется автоматически при достижении порога коинов, чисто мотивационный элемент;
- магазин коинов — возможность обменивать коины на бонусы (доп. консультация, скидка на следующий курс, сертификат с отличием); механику стоит заложить с начала разработки, даже если сначала магазин пуст.

## 5. Домашка бот

Отдельный мини апп для назначения и проверки домашних заданий, вынесенный из Основного бота из-за сопоставимого объёма логики с Серт ботом. Использует тот же общий «Конструктор заданий», что и Серт бот (см. раздел «Общая инфраструктура»).

### Назначение задания (со стороны админа)

В интерфейсе конкретной группы (том же, где настраивается расписание и материалы) админ привязывает домашнее задание к дате/уроку:
- название задания;
- прикреплённый файл задания (PDF/Word/картинки, содержимое не обрабатывается ботом);
- описание (опционально);
- дедлайн сдачи (календарь);
- тип формата ответа ученика — по той же типизации, что и в Серт боте:
  - тип 1 — тест с вариантами A–D/A–F;
  - тип 2 — ввод конкретного ответа (в т.ч. через математическую клавиатуру);
  - тип 3 — свободный текстовый ответ с возможностью приложить фото решения, проверяется вручную.

Дедлайн настраивается как жёсткий (форма сдачи закрывается после дедлайна) или мягкий (сдача после дедлайна возможна, но помечается как просроченная и/или получает автоматический штраф к баллу).

### Проверка (со стороны админа)

Отдельный интерфейс со списком сданных работ по каждому заданию, с фильтром «непроверенные / проверенные / просроченные». При открытии сдачи админ видит ответы ученика (текст + приложенные фото для типа 3), ставит балл (по каждому вопросу или общий — выбор реализуется настройкой) и оставляет текстовый комментарий/фидбек. Комментарий — полноценная часть интерфейса, а не второстепенная опция, так как акцент здесь на обучении, а не только на оценке.

### Сторона ученика

В мини аппе ученик видит список заданий своей группы:
- активные (дедлайн не наступил);
- сданные (ожидают проверки);
- проверенные (с баллом и комментарием админа);
- просроченные (не сдано вовремя — триггерит штраф в Основном боте через общую систему коинов).

Ответ автоматически сохраняется в черновик, чтобы не терялся при случайном закрытии мини аппа.

## 6. Материал бот

Мини апп для хранения и выдачи учебных материалов участникам курсов.

### Структура

Иерархия: курс → урок/тема → материалы этого урока. Типы материалов: видео, PDF, документ, презентация, текстовый материал (введённый админом вручную, без файла).

Доступ к материалам курса имеют только пользователи с активной учётной записью в этом курсе — проверяется через общую базу данных (ту же, в которую пишет Регистратор бот). Материалы одного курса не видны участнику другого курса.

### Загрузка материалов

Происходит со стороны Админ бота: в интерфейсе группы (том же, где настраивается расписание в Основном боте и домашние задания в Домашка боте) админ выбирает урок из календаря и прикрепляет к нему материал — так материалы автоматически привязываются к дате и теме без дублирования ввода.

Для материалов, не привязанных к конкретной дате (общий справочник, доп. литература, шаблоны), предусмотрена отдельная категория «Общие материалы курса».

### Настройка видимости

Материал можно открыть:
- сразу всем участникам;
- либо автоматически только после наступления даты/времени урока — до занятия ученики его не видят, сразу после начала занятия материал появляется в мини аппе. Это защищает от ситуации, когда ученики заранее скачивают видео и пропускают живой урок.

### Оплата и доступ

Для платных курсов применяется та же проверка, что и в Регистратор боте: если у пользователя просрочена или не подтверждена оплата, доступ к материалам текущего этапа блокируется автоматически, без участия админа. Уже оплаченные ранее материалы остаются доступны.

### Интерфейс ученика

- список папок по урокам с пометкой «просмотрено / не просмотрено» (вручную кнопкой либо автоматически при открытии видео);
- поиск по названию темы;
- фильтр по типу файла (видео / документ / текст).

## Общая инфраструктура (единая API система)

### Единая база пользователей

Ключ идентификации — telegram user_id. Один и тот же пользователь может иметь роли одновременно в нескольких ботах (например быть учеником в Основном боте и сдавать тест в Серт боте). Идентификация происходит через общий сервис авторизации, а не через отдельные базы у каждого бота.

### Общая база курсов и групп

Курсы создаются один раз в Регистратор боте, но используются во всех остальных ботах: Основной бот берёт расписание этой же группы, Материал бот — материалы этой же группы, Домашка бот — домашние задания этой же группы, Серт бот может быть привязан к курсу как «сертификатный тест по итогам курса».

### Центральная админ-панель

Админ бот — управляющее ядро всей системы (см. раздел 1).

### Единый конструктор заданий

Общий внутренний сервис, которым пользуются Серт бот и Домашка бот. Умеет создавать задания трёх типов, хранить черновики, принимать ответы, считать баллы. Разница между ботами не в структуре задания, а в контексте использования: Серт бот — формальные сертификатные тесты с рейтингом, Домашка бот — повседневная учебная работа, привязанная к конкретному уроку и группе. Такой подход исключает дублирование логики и упрощает добавление новых типов заданий в будущем.

### Единый файловый сервис

Файлы прикрепляются в нескольких ботах: задания и решения (Серт, Домашка), чеки об оплате (Регистратор), рукописные решения (Серт, Домашка), учебные материалы (Материал). Все файлы хранятся через единый сервис с привязкой к конкретной сущности (задание, анкета, сдача домашки, материал), а не как разрозненные file_id в разных таблицах — это упрощает архивирование, экспорт и резервное копирование.

### Единый планировщик задач (дедлайны и уведомления)

Общий паттерн «событие → время → автоматическое действие/уведомление» повторяется во всей системе:
- дедлайн варианта в Серт боте;
- дедлайн оплаты в Регистратор боте;
- предупреждение за 10 минут до онлайн-урока и автоотправка видео/документа в Основном боте;
- дедлайн сдачи домашнего задания в Домашка боте;
- открытие материала по времени в Материал боте.

Все эти сценарии реализуются через один общий планировщик (cron/очередь задач), а не отдельными таймерами в каждом боте.

### Система ролей

Помимо ролей «админ» и «ученик» вводится промежуточная роль — куратор/ассистент, который может:
- проверять письменные работы в Серт боте и Домашка боте;
- подтверждать оплату в Регистратор боте;

но не имеет доступа к созданию курсов, вариантов и изменению правил геймификации. Эта роль особенно важна для Домашка бота — при большом числе учеников проверка всех работ лично админом становится нереалистичной, поэтому роль закладывается в архитектуру с самого начала, а не добавляется позже.

### Журнал действий (аудит)

Общий лог действий: кто, когда и что изменил (удаление анкет, блокировка аккаунтов, выставление баллов и т.д.) — для отслеживания ошибок и разбора спорных ситуаций с учениками.

### Единая система коинов и достижений

Коины в Основном боте и рейтинг в Серт боте объединяются в одну систему достижений — например, хороший результат сертификатного теста начисляет бонусные коины в Основном боте. Это создаёт у ученика ощущение целостного прогресса вместо нескольких несвязанных показателей в разных ботах.

### Агрегированные уведомления

Вместо отдельных уведомлений от каждого бота (новое домашнее задание, приближающийся дедлайн теста, новый материал) пользователю отправляется одно сводное уведомление по расписанию (например раз в день), собранное из всех ботов через общий сервис уведомлений — это снижает информационную усталость пользователей.

## Сводная схема связей между ботами

| Бот | Создаёт данные | Использует данные из |
|---|---|---|
| Админ бот | курсы, группы, варианты, расписания, домашние задания, материалы | — (управляющее ядро) |
| Серт бот | результаты тестов, рейтинг | Конструктор заданий, Файловый сервис, Планировщик |
| Регистратор бот | анкеты, учётные записи, статус оплаты | Общая база пользователей и курсов |
| Основной бот | коины, штрафы, посещаемость | Расписание (Админ бот), результаты Серт бота, статус Домашка бота |
| Домашка бот | сданные работы, баллы, комментарии | Конструктор заданий, Файловый сервис, Планировщик, статус влияет на коины Основного бота |
| Материал бот | статус просмотра материалов | Расписание (Админ бот), статус оплаты (Регистратор бот) |
